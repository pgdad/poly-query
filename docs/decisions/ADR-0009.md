# ADR-0009: Conformance oracle strategy

**Status:** Accepted (2026-10-10)

## Decision

Expected results are written in the `.pqt` test files. For tests whose semantics coincide with SQLite (flag `oracle sqlite`), `tools/validation/oracle_check.py` re-derives the result with Python's stdlib `sqlite3` and compares it to the stored expectation using the acceptance comparison rules. Tests involving PolyQuery-specific semantics (DECIMAL scale, strict errors, LIKE case sensitivity, integer division by zero, type names) carry hand-written expectations reviewed against the spec.

## Rationale and consequences

Never uses any PolyQuery engine output as authority. The harness and oracle tooling are written in Python but are infrastructure, independent from `implementations/python` (no shared code; the Python engine agent never sees the harness internals beyond the public CLI contract).
