# ADR-0007: Implementation isolation: fresh workspaces + sandbox instead of plain worktrees

**Status:** Accepted (2026-10-10)

## Decision

A Git worktree shares the object database with the main repository, which would let an agent read other languages' code via `git show`. Each attempt therefore gets a **fresh repository** under `/srv/polyquery/runs/<run-id>/workspace` that contains only the frozen spec, public tests/fixtures, dataset generators and its own `implementations/<lang>/` tree. The agent runs inside a bubblewrap sandbox (`tools/orchestration/sandbox.sh`) in which `$HOME` is an empty tmpfs, the main repository and all other workspaces are invisible, host credentials (env vars, ~/.aws, ~/.ssh, ~/.claude history) are absent, and supplementary groups, capabilities and setuid escalation (no_new_privs) are removed. After the attempt, the orchestrator exports the agent's commits with `git format-patch` and applies them to a branch in the main repository, rejecting any patch that touches paths outside the language directory.

## Rationale and consequences

Ubuntu 24.04's AppArmor forbids unprivileged user namespaces, so bwrap runs via passwordless sudo and immediately drops to the invoking uid. Docker Desktop (the only Docker on the host) cannot bind host toolchains, so containers are provided for reproducibility (Dockerfile) but the sandbox is the isolation mechanism for agent runs. Network access remains (the agent needs the model API); this is documented as a residual risk.
