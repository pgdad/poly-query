# ADR-0018: Application family — embedding API and the pqledger CLI

**Status:** Accepted (2026-10-14)

## Context

Every engine passes the full conformance suite, but none has been used as a library by a real
program. The project owner asked for each implementation, including both assembly engines, to
build a meaningful command-line application on its own engine, with user documentation and
developer documentation for using the engine from any program in that language.

## Decision

1. **One application for all eight:** `pqledger`, a personal-finance CLI (bank CSV import with
   configurable formats, duplicate detection, rule-based categories, reports, budgets, ad-hoc
   SQL). It exercises CSV ingestion, `DECIMAL` money, joins, `LIKE`, aggregation, sorting and
   PQCF save/open, and its output can be compared byte for byte.
2. **Normative application spec** `spec/apps/pqledger.md` and **embedding contract**
   `spec/apps/embedding.md` (application spec 1.0.0; the engine spec is unchanged). The embedding
   API's shape is left to each language (idiomatic); its operations, typed values, error codes
   and packaging form are fixed. Assembly engines provide a C-ABI library with a declarations-only
   C header (the one `.h` file their policy check allows) and write the application in assembly.
3. **The ledger file layout is normative** (three PQCF tables), so ledgers are interchangeable
   between implementations; the tests seed ledgers written by the test harness, and a later
   cross-implementation matrix checks interoperability directly.
4. **In-process use is required and checked:** the validator runs every case under `strace` and
   fails a run that starts an engine process or connects a socket. That reports and category
   resolution run as SQL inside the engine is checked by review.
5. **Expected outputs** come from a reference implementation (`tools/validation/pqledger_ref.py`)
   that uses no engine; `query` and embed-demo expectations are computed from the scenario data
   by `tools/validation/pqledger_cases.py`. Hidden cases (`tests/apps/hidden/`) include a
   ~100,000-transaction ledger.
6. **Run plan:** task `app-pqledger`, one attempt per engine, prompt template
   `experiments/prompts/track-a-app.md`. The six engines run as a wave; the assembly engines run
   as continuation chains with the assembly policy check before merging.

## Consequences

Validation adds the application suite (`app_exit`) and a deliverables check (`docs_exit`) to the
usual full conformance, HTTP, modes and expression-limit checks; the capability set must not
change. Documentation quality is assessed afterwards by read-only reviewer agents.
