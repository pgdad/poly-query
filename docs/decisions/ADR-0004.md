# ADR-0004: DECIMAL limited to 18 digits of precision

**Status:** Accepted (2026-10-10)

## Decision

DECIMAL(p,s) requires p ≤ 18 so that unscaled values fit in int64 in every language. Arithmetic requiring more digits raises NUMERIC_OVERFLOW; intermediates must be exact.

## Rationale and consequences

Keeps fixed-precision semantics exact and portable without big-decimal libraries in Track A (Rust/Go/SBCL have no stdlib decimal; Java/Python do). Division of decimals yields FLOAT64 to avoid specifying decimal division scale rules.
