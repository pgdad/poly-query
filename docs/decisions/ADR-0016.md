# ADR-0016: Assembly languages in the experiment — kernel family now, complete engines as a separate cohort

**Status:** Accepted (2026-10-11): the kernel experiment family, and a pilot for
complete assembly engines ($300 cap, x86-64 Phase 1; glibc allowed; AArch64 agents on
the ARM host)

## Context

The brief defines the six high-level languages as complete engines and the two
assembly languages as native-kernel implementations. After M10 the later
experiment families (requirement change, refactoring, debugging, optimization,
code review) covered only the engines.

## Decision

1. The assembly languages get their own kernel experiment family, with the same
   kinds of tasks as the engines: CR-4 (128-bit kernels, `spec/changes/kernels-i128.md`),
   CR-5 (behaviour-preserving restructuring, `spec/changes/kernel-refactor.md`),
   debugging with a symptom-only report and hidden-only failing tests,
   throughput optimization, and rubric code review. Kernel tasks have hidden
   acceptance tests (`tests/kernels-hidden/`), validated natively on x86-64 and
   on the ARM host.
2. Kernel results form a **kernel cohort** in reports 1–8. They are never ranked
   against the engines, whose tasks are not comparable in size.
3. Complete assembly engines are a separate, optional research step
   (`docs/methodology/assembly-engines-plan.md`), started only with an explicit
   pilot decision; if run, they form their own cohort.

## Consequences

* The kernel ABI gains a revision number (`pqk_abi_revision()`), and the
  version stays 1, so engines are unaffected.
* The AArch64 kernel agent cannot measure performance (no native hardware in
  its sandbox); its optimization run reasons from the microarchitecture, and
  the independent before/after measurement on the ARM host is the result. This
  asymmetry is reported with the numbers.
